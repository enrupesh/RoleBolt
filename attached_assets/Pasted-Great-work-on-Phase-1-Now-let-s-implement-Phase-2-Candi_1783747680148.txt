Great work on Phase 1.

Now let's implement **Phase 2: Candidate Context**.

The architecture already supports multiple context levels, so now we need to activate `context.level = "candidate"`.

## Goal

When a recruiter opens a candidate profile, the AI should automatically understand that every question is about that candidate.

The recruiter should never need to type the candidate's name.

---

## Candidate Context

When a candidate is selected, provide the AI with:

* Candidate profile
* Resume text
* Resume summary
* AI score
* Score breakdown
* Assessment answers
* Interview brief
* Job description
* Rubric
* Skills
* Experience
* Projects
* Education
* Certifications
* Notice period
* Salary expectation (if available)

The AI should use only this context.

---

## Example Questions

* Summarize this candidate.
* Why did this candidate score 84?
* What are the strengths?
* What are the weaknesses?
* Which required skills are missing?
* Is this candidate a good fit?
* Should I hire this candidate?
* Generate interview questions.
* Explain the assessment performance.
* Compare this candidate with the job requirements.

---

## Recommendation Card

Every response should include:

Recommendation

Interview / Hold / Reject

Evidence-backed explanation.

## Navigation

From the Candidate Profile page, clicking "Ask Rolebolt" should automatically open the Copilot with the selected candidate as the active context.

The recruiter should never have to manually select the candidate again.

The experience should feel seamless.

Let's keep the same backend architecture and simply activate the candidate context using the existing context model.
